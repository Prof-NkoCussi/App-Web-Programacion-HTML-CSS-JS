51. Reencuentro con JavaScript

Qué hace en la página y cómo se conecta app.js

JavaScript es el lenguaje de programación que aporta interactividad y lógica a las páginas web. Permite que los sitios respondan a las acciones del usuario, cambien contenido en tiempo real y realicen tareas dinámicas en el navegador.

Consola · salida esperada
Sofía: Aprobado

¿Qué hace JavaScript?

  • Responder a acciones del usuario: detecta eventos como clics, movimientos del mouse o teclas presionadas.
  • Cambiar contenido: modifica textos, imágenes y estilos en tiempo real, sin recargar la página.
  • Validar formularios: comprueba que los datos sean correctos antes de enviarlos.
  • Realizar tareas dinámicas: controla animaciones, menús, carruseles y mucho más.

Cómo se conecta app.js: <script src="app.js"></script> va al final del <body>, justo antes de </body>. src es el archivo que se carga, como el href del <link>: app.js, en la misma carpeta.

Idea clave: HTML estructura el contenido, CSS lo estila y JavaScript añade el comportamiento, haciendo que las páginas web sean interactivas y dinámicas.

52. DOM y selección de elementos

La página vista desde JavaScript

El DOM (Document Object Model) representa la página HTML como una estructura de elementos que JavaScript puede acceder y modificar. A través del DOM, podemos encontrar elementos, cambiar su contenido, estilos y comportamiento.

¿Qué es el DOM?

El DOM es una representación en forma de árbol de todos los elementos de una página web. Cada elemento HTML se convierte en un objeto que JavaScript puede seleccionar, leer y modificar.

Es el árbol de etiquetas de la lámina 27 (TP7), visto desde JavaScript. Se entra por document: la página entera.

  • getElementById()

    Selecciona un elemento por su id, sin #: document.getElementById("titulo")

  • querySelector()

    Selecciona el primer elemento que coincide con un selector CSS: document.querySelector(".btn")

Idea clave: el DOM permite que JavaScript encuentre elementos en la página y cambie su contenido, estilos y comportamiento.

53. Cambiar el contenido

textContent e innerHTML

Cuando ya tenemos un elemento, podemos cambiar lo que muestra. textContent cambia su texto e innerHTML cambia el HTML que tiene adentro. La página se actualiza en el momento, sin recargarla.

  • textContent: todo es texto

    Lo que le damos se muestra tal cual. Si trae etiquetas, se ven como letras: <strong> no pone nada en negrita.

  • innerHTML: interpreta etiquetas

    Lee el texto como HTML: <strong> se ve en negrita, como si estuviera escrito en index.html.

Recomendación: para mostrar lo que escribe el usuario, usá textContent. Con innerHTML, las etiquetas que escriba pasarían a ser parte de la página; con textContent se muestran tal cual.

Idea clave: textContent cambia el texto de un elemento y muestra todo como texto; innerHTML cambia su HTML e interpreta las etiquetas.

54. Cambiar los estilos

.style y classList: add, remove y toggle

Con .style cambiamos una propiedad de CSS; con classList, le ponemos o le sacamos clases de estilos.css.

  • .styleCambia una propiedad

    font-size → fontSize

  • add()Pone una clase
  • remove()Saca una clase

55. Eventos e interacción

onclick y addEventListener()

Los eventos permiten que JavaScript reaccione a las acciones del usuario, como clics, escribir texto o mover el mouse, haciendo que una página web sea interactiva.

¿Qué es un evento?

Un evento es una acción que realiza el usuario en la página web, como hacer clic, escribir o mover el mouse. JavaScript puede “escuchar” esos eventos y ejecutar una función cuando ocurren.

"click" se activa cuando el usuario hace clic en un elemento.

Pasos de la interacción

  1. El usuario hace clic: realiza una acción, como hacer clic en el botón.
  2. JavaScript detecta el evento: se ejecuta la función asociada al evento.
  3. La página cambia el contenido: la función modifica el contenido y se muestra el resultado.

  • onclick, en el HTML

    <button onclick="avisar()"> llama a la función al tocar el botón, como en las láminas 53 y 54.

  • addEventListener(), en app.js

    addEventListener("click", avisar) deja el HTML sin JavaScript. Es la forma recomendada. La función va sin paréntesis.

Idea clave: los eventos conectan las acciones del usuario con el comportamiento de JavaScript, permitiendo respuestas dinámicas en la página.

+ Para profundizar

Un poco más sobre cada lámina

Lámina 51

¿Por qué el script va al final?

El navegador lee el HTML de arriba hacia abajo y corre cada <script> apenas lo encuentra. Si app.js se carga en el <head>, los elementos del <body> todavía no existen: getElementById() devuelve null y la consola muestra un error.

Otra forma: dejarlo en el <head> con defer, que espera a que se cargue todo el HTML.

<script src="app.js" defer></script>

Se usa en botones que responden al clic, formularios que revisan los datos, carruseles de imágenes y menús desplegables.

Buenas prácticas: código claro, con sangría y funciones separadas; nombres descriptivos; comentarios; y probá en el navegador que funcione como esperás.

Lámina 52

Seleccionar varios elementos

querySelector() trae solo el primer elemento que coincide. Para traerlos todos:

  • querySelectorAll(".tarjeta"): todos los que coinciden con el selector.
  • getElementsByClassName("tarjeta"): todos los que tienen esa clase, sin el punto.

Devuelven una lista de elementos que se recorre con for...of, como un array (TP4).

Buenas prácticas: nombres claros para los id y las clases; verificá que el elemento exista antes de modificarlo (si no lo encuentra, da null), y preferí querySelector() para selectores simples, ya que es más flexible y moderno.

Láminas 53 y 54

Contenido y estilos: un poco más

textContent también sirve para leer: titulo.textContent es el texto que tiene ahora el título.

Lo que escribe el usuario

Si alguien escribe <b>Ana</b>, con textContent se ve así, con las etiquetas. Con innerHTML se vería “Ana” en negrita, y cualquier otra etiqueta pasaría a ser parte de la página.

.style usa camelCase: border-radius → borderRadius. El valor va entre comillas, con su unidad: "20px".

¿.style o classList? .style, para un cambio puntual, como un color al azar; para varios cambios juntos, una clase. Lo que pone .style le gana a las clases, y se borra con un texto vacío: tarjeta.style.color = "";

Lámina 55

Otros eventos

  • "input": se activa cuando el usuario escribe o cambia el contenido de un campo de texto.
  • "mouseover": se activa cuando el cursor del mouse pasa sobre un elemento.
  • "submit": se activa cuando se envía un formulario. Lo usamos en el TP14.

Cuidado con los paréntesis

addEventListener("click", avisar()) ejecuta avisar() una sola vez, al abrir la página, y el clic no hace nada. Va el nombre solo: avisar.

Buenas prácticas: usá addEventListener(), nombres descriptivos y la lógica en funciones, y probá cada evento en el navegador.
