33. Tablas

table, tr, th, td, thead y tbody

Las tablas organizan información en filas (horizontales) y columnas (verticales), y cada celda contiene un dato. Son muy útiles para mostrar datos de forma clara, como listas, horarios, precios o resultados.

Etiquetas principales

  • <table>: define el contenedor de la tabla.
  • <tr>: define una fila de la tabla.
  • <thead>: agrupa las filas de encabezado.
  • <th>: define una celda de encabezado (título).
  • <tbody>: agrupa las filas de contenido principal.
  • <td>: define una celda de datos.

Importante

Las tablas son muy útiles para mostrar datos, como listas, horarios, precios o resultados. Usalas solo cuando la información tenga una estructura tabular real (filas y columnas).

Idea clave: las tablas organizan los datos en filas y columnas. Deben usarse para mostrar información tabular, no para armar el diseño general de una página.

34. Formularios

form, label e input

Los formularios permiten que los usuarios ingresen y envíen información: para registrarse, iniciar sesión, enviar mensajes o completar encuestas. Cada dato se escribe en un campo, y los datos se envían a un servidor para ser procesados.

Etiquetas de un formulario

  • <form> contiene todos los campos del formulario.
  • <label> asocia un texto descriptivo con un campo.
  • <input> crea diferentes tipos de campos de entrada.

for, id y name

  • El for del <label> tiene que ser igual al id de su campo: así quedan unidos. Cada id va una sola vez.
  • name es el nombre del dato: al enviar, cada valor viaja con su nombre (email=ana@mail.com). Un campo sin name no se envía.
  • required: campo obligatorio (ver “Para profundizar”).

Idea clave: los formularios permiten que los usuarios ingresen y envíen información. Se utilizan para recolectar datos y comunicarse con los usuarios.

35. Tipos de campo

input, textarea, select y button

El atributo type del <input> indica qué tipo de campo se crea. Además, <textarea> permite ingresar varias líneas de texto, <select> crea una lista desplegable y <button>, un botón.

  • textTexto

    Para ingresar texto simple.

  • emailCorreo electrónico

    Para ingresar un email.

  • passwordContraseña

    Oculta el texto ingresado.

  • telTeléfono

    Para ingresar un número de teléfono.

  • checkboxCasilla de verificación

    Para seleccionar varias opciones.

  • radioBotón de opción

    Para elegir una sola opción.

Idea clave: el atributo type define qué campo crea el <input>. <textarea>, <select> y <button> completan el formulario.

36. Contenedores y HTML semántico

div y las etiquetas con significado

Un contenedor agrupa elementos y organiza la página en secciones. El HTML semántico usa etiquetas que dicen qué es cada parte.

Importante

<div> es un contenedor genérico: no indica el significado del contenido. Las etiquetas semánticas, sí: ayudan a usuarios y navegadores a entender la estructura de la página.

Idea clave: los contenedores organizan el contenido. Las etiquetas con significado mejoran la legibilidad y la accesibilidad de la página.

+ Para profundizar

Un poco más sobre cada lámina

Lámina 33

Tablas accesibles: caption y scope

  • <caption> le pone un título a la tabla, justo después de <table>: <caption>Horarios</caption>.
  • scope indica si un <th> es el encabezado de una columna (col) o de una fila (row): <th scope="col">Día</th>.

Los lectores de pantalla, que leen la página en voz alta para personas ciegas, usan estos datos para anunciar el título de la tabla y la columna de cada celda.

Buenas prácticas

  • Usá <th> para los encabezados: identifican cada columna.
  • Mantené los datos claros y ordenados: textos breves y consistentes.

Lámina 34

Campos obligatorios: required

Con required, el campo es obligatorio: si queda vacío, el navegador no envía el formulario y muestra un aviso al lado del campo.

En un campo type="email", además, revisa que lo escrito tenga forma de email, con @.

Probalo en el resultado de la lámina 34: tocá “Enviar” con los campos vacíos, o escribí un email sin @.

Buenas prácticas

  • Usá etiquetas <label>: ayudan a los usuarios a entender qué información deben ingresar.
  • Pedí solo los datos necesarios: no solicites información que no sea importante.

Lámina 35

Opciones, botones y ayudas

El value es el dato que se envía. En un <select>, cada <option> tiene el suyo, y el texto de adentro es lo que ve el usuario. En los botones de opción, se envía el value del marcado: opcion=1.

placeholder muestra un texto de ayuda dentro del campo, que se borra al escribir: placeholder="tu@email.com". No reemplaza al <label>.

Un <button type="submit"> envía el formulario. Con type="button" es un botón que no envía nada: lo usamos con JavaScript en el TP13.

Buenas prácticas

  • Escribí botones claros: usá textos descriptivos, como “Enviar” o “Registrarse”.

Lámina 36

¿section o article?

  • <article> es un contenido autónomo: se entiende solo, aunque lo saquemos de la página, como una noticia o una publicación.
  • <section> agrupa contenido de un mismo tema y casi siempre lleva su título. En el ejemplo, “Últimas noticias” es una <section> y cada noticia, un <article>.

¿Por qué es importante?

  • Mejor estructura: el contenido queda claro y ordenado.
  • Facilita el mantenimiento: el código se entiende y se modifica mejor.
  • Mejora la accesibilidad: ayuda a quienes usan lectores de pantalla.
  • Beneficia el SEO: los buscadores entienden mejor la página.
